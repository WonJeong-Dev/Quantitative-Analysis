## 폴더 안내

```text
assets/     아이콘 원본 (PNG·ICO·SVG)
backend/    Cloudflare Worker와 Firestore 규칙
  optional/ 선택형 Google Apps Script 프록시
dist/       자동 생성되는 웹 배포물 (HTML·PNG·ICO)
docs/       설계·설정·변경 기록
scripts/    빌드·검증·로컬 미리보기
src/        수정할 앱 소스
tests/      단위·통합·smoke·브라우저·보안 규칙 검사
```

[설계 가이드](docs/DESIGN.md) · [설정·배포 가이드](docs/SETUP.md) · [변경 기록](docs/CHANGELOG.md)

`dist/`는 빌드로 다시 만들 수 있습니다. 직접 수정하지 말고 `src/`와 `assets/`를 수정하세요. `artifacts/`는 브라우저 검사 때만 생성되는 결과 폴더이며 배포하지 않습니다. SVG는 아이콘 편집 원본으로 보존하며 배포물에는 실행에 필요한 PNG·ICO만 복사합니다.

`backend/optional/gas_proxy.gs`는 기존 선택형 프록시입니다. 현재 Cloudflare Worker를 쓰는 구성에서는 배포할 필요가 없습니다. 기존 사용자 설정과의 호환을 위해 원본을 보존합니다.

## 개발과 실행

```sh
node scripts/build.cjs
node scripts/verify.cjs
node scripts/serve.cjs
```

- `src/app.js`: 앱·데이터·화면 연결. 기존 기능을 유지하며 점진적으로 분리했습니다.
- `src/investment.js`, `src/investment-ui.js`: 투자정책·시나리오·집중도·사전 고정 검증 계산과 화면.
- `src/domain.js`: 단위, 종목·계좌 식별, 원장, 가져오기 검증, 수익률, 백업 형식의 순수 함수.
- `src/styles.css`, `src/ux.js`, `src/index.html`: 반응형 화면·접근성·백업과 HTML 틀.
- `dist/index.html`: 빌드 결과. 직접 수정하지 않습니다.
- `backend/cloudflare_worker.js`: 시세 프록시. 자동 부채비율을 배수로 정규화하고 요청·응답 제한과 캐시를 추가했습니다.
- `backend/firestore.rules`: 유일한 보안 규칙 배포 원본입니다.
- `tests/fixture.js`: 로컬 서버에서만 주입되는 합성 데이터. 빌드·배포 HTML에 포함되지 않습니다.

미리보기 주소는 `http://127.0.0.1:4173`입니다. 실제 계정에 연결되지 않습니다. 운영 HTML을 배포하는 것과 구분하세요.

브라우저 검사는 Playwright와 Edge가 있는 환경에서 `node tests/browser.cjs`로 실행합니다. Playwright 모듈 경로는 `QA_PLAYWRIGHT` 환경변수로 지정할 수 있습니다. 기본 경로는 이번 작업에 사용한 로컬 런타임입니다. 다른 환경에서는 해당 환경의 설치 경로로 지정합니다.

## 달라진 판단·원장 정책

1. **부채비율**: 자동값은 배수로 통일합니다. 과거 수동값은 `%/배`를 선택하기 전까지 점수에서 제외하고, 주식의 해당 판단을 보류합니다. 값의 크기로 단위를 추측하지 않습니다.
2. **성장률**: PER은 이익 성장, PSR은 매출 성장을 사용합니다. 성장률이 없는 PER 입력에 기본 8%를 넣던 동작을 제거했습니다. 이에 따라 일부 점수·등급·추정가는 구버전과 달라질 수 있습니다.
3. **계좌·종목**: 종목코드와 시장·유형·실계좌별로 보유를 묶습니다. 기존 `general` 등은 그대로 유효하며 `general:증권사명`처럼 별칭을 붙여 분리할 수 있습니다.
4. **당일 순서**: 같은 날 매수·매도가 섞이면 실제 체결순번을 기록합니다. 순번이 없거나 중복이면 잔고는 관측하되 원가·손익은 미확정으로 표시하고 집계에서 제외합니다.
5. **초과 매도**: 부족 수량을 0으로 지우지 않습니다. 해당 포지션은 확정 손익·성과·자산 합계에서 제외되고 원장 확인 안내에 나타납니다.
6. **과거 판단**: 과거 날짜로 입력한 거래에는 오늘 판단을 붙이지 않습니다. 기존 스냅샷의 시점이 검증되지 않았으면 등급별 성과에 귀속하지 않습니다. 거래 대상·일자·매매구분 변경 시 스냅샷을 무효화합니다.
7. **판정 로그**: 규칙 `v5.5`, 스키마 2. 하루 최초 준비된 관측을 저장하며, 5.5부터 보안 규칙이 수정·삭제·과거 날짜 생성을 막습니다(전방수익률 `fwd`만 추가). 관측 후 다음 정규장 시가→지평 마지막 완료 봉 종가를 평가합니다. 체결 비용·배당을 포함한 총수익률은 아닙니다. 지수는 동일 시작·종료 세션인 경우만 비교합니다.
8. **자료 부족**: 판단 감사의 `U`는 관측 불충분입니다. `B/B*/C`는 관측된 변화의 방향을 비교한 값이지 원인 확정이 아닙니다. 검증 화면의 경향도 통계적 유의성 판정이 아닙니다.

기존 추천 임계값을 최근 결과에 맞춰 튜닝하지 않았습니다. 단위 오류·결측 처리와 성장 입력의 의미를 바로잡은 변경입니다. 실제 투자 판단력의 검증은 이 판부터 쌓이는 일관된 관측으로 별도 수행해야 합니다.

## 웹·모바일 개선

320~1440px에서 페이지 가로 넘침을 점검했습니다. 작은 화면의 카드·입력창·모달, 하단 관심종목/거래·자산 메뉴, 보유 필터, 검색 지우기, 범례·수동 입력 접기, 44px 터치 영역, 키보드 포커스·모달 초점 고정, 스크린리더 이름, 오프라인 상태와 입력 중 재렌더 보호를 적용했습니다.

기존 장중 시세·차트·기업행사·환전 기능은 유지했습니다. 전면 프레임워크 전환이나 추가 유료 서비스는 도입하지 않았습니다.

## 검증과 남은 운영 확인

이번 실행 결과와 인수 항목은 [변경 및 검증 기록](docs/CHANGELOG.md)을 참고하세요. 단위/통합/기존 smoke와 합성 데이터 브라우저 검사는 운영 Firebase 보안 규칙 검증을 대신하지 않습니다.

운영 배포 전에는 현재 Firebase 규칙을 백업한 후 이 저장소의 규칙과 대조하고, 허용 사용자 두 명의 실제 계정 분리를 확인해야 합니다. 이 작업에서 실계정 로그인·운영 데이터 복구·원격 배포는 하지 않았습니다.
