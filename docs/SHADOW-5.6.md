# 그림자 장부 · 횡단면 분모 · 제안 승급 — 명세 v1 (2026-10-16)

대상: 앱 v5.6 / 워커 v7.0 / **`RULE_VER`는 v5.5 그대로** (판정 로직 불변)
선행: `docs/CHANGES-5.5.md` · `claude/QA-Stock-Board-개선필요사항-감사-…-0929.md` §3·§6

이 문서는 **코드보다 먼저** 규칙을 고정하기 위한 것이다. 숫자를 본 뒤에 규칙을 고르면
그것이 §22-⑤가 금지하는 동작이다. 여기 적힌 정의는 `qa_prereg`에 동결한 뒤에만 구현한다.

---

## 0. 설계 원칙 네 줄

1. **판정에 들어가는 새 상수를 만들지 않는다.** 진입·청산·분모·귀속 어디에도 임계값이 없다.
   승급 **심사**에만 문턱 4개가 있고, 셋은 기존 값(`GL_MIN_N` 30 · `GL_MIN_DAYS` 250 ·
   국면은 부호라 2)의 재사용이며 코드가 부팅 때 일치를 검사한다. **새 값은 `minUniq=15`
   하나뿐이고** 0929 감사 §3-6의 방법론 처방에서 왔다 — CONST_LOG에 그렇게 적는다.
   넷 다 표시·심사 전용이며 판정 경로에 들어가지 않는다.
2. **모든 산출물은 `qa_gradelog`의 순수함수다.** 상태를 저장하지 않으므로 언제든 전량
   재계산되고, 규칙이 바뀌면 과거가 자동으로 새 규칙으로 다시 읽힌다.
3. **코드는 스스로 상수를 바꾸지 않는다.** 4층은 후보를 *제시*하고 새 arm을 추가할 뿐이다.
4. **판정 경로를 한 줄도 건드리지 않는다.** `compute` · `classifyDetail` · `TIER_SPEC` 불변.

## 1. 횡단면 분모 `m{h}` — 외부 충격의 유일하게 정직한 처리

### 1.1 왜 '참작'이 아니라 '분모'인가

외부 충격(전쟁·금리·정책)을 예외 규칙으로 참작하면, 그 규칙은 **어떤 실패든 사후
정당화할 수 있는 자유 파라미터**가 된다. 한 번 허용하면 "그건 금리 때문", "그건 섹터
로테이션 때문"으로 확장되고, 모든 오판이 (C) 불가피로 흡수된다 — §22-㉒가 경계하는
실패의 가장 비싼 형태다.

분모를 바꾸면 같은 일이 **자유도 0**으로 처리된다. 전 종목이 −20% 가는 날은 중앙값도
−20%이므로 초과수익에서 상쇄된다. 탐지기도, 임계값도, 사람 판단도 없다.

### 1.2 정의

```
m{h}(i, d) = r{h}(i, d) − median{ r{h}(j, d) : j ∈ U(i, d) }
U(i, d)    = 같은 문서 d 의 행 중  market(j) == market(i)  ∧  type(j) == type(i)
             ∧  r{h}(j, d) 가 존재  ∧  q{h}(j, d) 가 없음(오염 아님)
mn{h}(i,d) = |U(i, d)|
```

- **자기 자신을 포함한다.** 제외하면 i마다 다른 모집단이 되어 비교가 흐려지고, N=57에서
  중앙값 이동은 무시할 수준이다. 포함이 표준이고 선택의 여지가 없다.
- **시장 × 자산유형**으로 나눈다. `inputs[id].cls.{market,type}`에 이미 있다. ETF는 지수를
  추종하므로 주식과 섞으면 중앙값이 지수 쪽으로 끌린다.
- **최소 N 임계를 두지 않는다.** 대신 `mn{h}`를 항상 함께 보여준다. 임계를 두면 그 숫자가
  §20에 귀속되지 않는 새 상수가 된다. 관측수를 보이고 읽는 사람이 판단한다(§22-㉖).

### 1.3 저장하지 않는다 — 읽을 때 계산한다

`m{h}`는 문서 안의 `fwd.*.r{h}` 들만으로 결정되는 **순수함수**다. 저장하면
① 백필이 진행되며 값이 변하고 ② 불변 로그에 가변 파생값이 생기고 ③ Firestore 쓰기가
는다. 읽을 때 계산하면 셋 다 사라지고 **언제 읽어도 현재 r 집합과 정합**이다.

→ Firestore 스키마 변경 없음 · 규칙 변경 없음 · 마이그레이션 없음.

### 1.4 주 결과변수와 보조 결과변수

| | 정의 | 역할 |
|---|---|---|
| **주** `x60` | 지수(^GSPC/^KS11) 대비 60거래일 초과수익 | 기존 H1~H7이 쓰는 축. 바꾸지 않는다 |
| **보조** `m60` | 같은 날짜·같은 시장·같은 유형 중앙값 대비 | 외부 충격 중화. 섹터·시장 공통 팩터까지 상쇄 |

둘을 **나란히** 보고한다. 하나를 고르면 그 선택이 사후 선택이 된다. 방향이 갈리면
그 자체가 정보다(공통 팩터가 결과를 지배한다는 뜻).

## 2. 그림자 장부 — 1·2층

### 2.1 무엇을 더하고 무엇을 더하지 않는가

`fwd`는 이미 "d일에 사서 h거래일 뒤 판다"는 가상 체결이다. 그림자 장부가 더하는 것은
**진입 규칙의 비교**이지 새 수익률이 아니다.

**v1에서 의도적으로 넣지 않는 것 — 전부 자유 파라미터이기 때문이다**

| 뺀 것 | 이유 |
|---|---|
| 경로 의존 청산(손절·트레일링·목표가 도달) | 임계값이 최소 2개 새로 생긴다. 지평은 이미 사전등록된 20·60·120이다 |
| 자본 제약·동시보유 한도 | 한도 숫자가 §20 어디에도 귀속되지 않는다 |
| 포지션 사이징(확신도 비례 등) | 가중 함수 자체가 추정 대상이 된다 |
| 거래비용·슬리피지 | 추정치이고, arm 간 **차이**에는 거의 영향이 없다(진입 빈도가 비슷할 때) |

v1은 **동일가중 사건 포트폴리오**다. 진입 사건 하나 = 1단위. 어떤 날의 포트폴리오
초과수익 = 그날 열려 있는 사건들의 초과수익 평균. 자유 파라미터 0개.

경로 의존 청산은 표본이 2국면을 넘긴 뒤 **별도 사전등록**으로만 연다.

### 2.2 진입 사건의 정의

독립 관측 단위는 **등급 진입 이벤트**다(감사 §3-5). 같은 종목의 연속된 날은 독립이 아니다.

```
진입(i, d) ⟺ arm.enter(row_d(i)) == true  ∧  arm.enter(row_{d−1}(i)) != true
엠바고     : 같은 종목은 청산일(d + h 거래일) 이전에 재진입하지 않는다
```

`d−1`은 같은 rv·같은 settings를 가진 **직전 로그 문서**다. 직전 문서가 없으면(수집 공백)
그 날은 진입 판정을 하지 않는다 — '처음 본 날'을 전이로 세면 공백마다 가짜 진입이 생긴다.

### 2.3 arm 5종 — 사전 고정

| 키 | 이름 | 진입 조건 (로그 열만 사용) | 묻는 질문 |
|---|---|---|---|
| **A** | 현행 | `tier ∈ {상, 중}` | 지금 규칙이 작동하는가 |
| **B** | 캡 해제 | `tierNoCap ∈ {상, 중}` | 하락추세 캡이 기회를 죽이는가 (**H3**) |
| **C** | 전등급 | `tier ∈ {상, 중, 하}` | 등급 하단까지 사면 나은가 |
| **D** | 무작위 | 그날 A와 **같은 개수**를 같은 모집단에서 무작위 추출 | **플라시보 — 영가설 분포** |
| **E** | 동일가중 보유 | 그날 로그의 전 종목 | **벤치마크 — 아무것도 안 하기** |

- **D·E가 없으면 A·B·C의 숫자는 읽을 수 없다.** A가 +3%p여도 D가 +3%p면 정보가 0이다.
- **D의 난수는 결정론적이다.** 시드 = `hash(rv + '|' + d)`. 같은 로그를 몇 번 돌려도 같은
  결과가 나와야 재현 가능하다. 구현은 xorshift32 한 줄.
- 지평은 arm 공통으로 **60거래일**(주 지평). 20·120은 함께 계산해 표로만 보인다.

### 2.4 산출 통계

arm별로, 주/보조 결과변수 각각에 대해:

```
N        진입 사건 수
U        고유 종목 수
med      초과수익 중앙값 (평균이 아니다 — 꼬리가 지배한다)
IQR      사분위 범위
hit      양(+) 비율
hit−base 같은 날짜 모집단의 양(+) 비율을 뺀 값
CI90     이동블록 부트스트랩 90% 신뢰구간 (블록 길이 = h, 날짜 단면으로 리샘플)
MDE      현재 N 기준 최소검출효과 — 지표 옆에 **항상** 함께 표시한다(감사 §3-6 ④)
```

**점추정만 보여주지 않는다.** 감사 §3-5가 지적한 대로 겹치는 창 때문에 유효 표본이
명목 N보다 훨씬 작다. 이동블록 부트스트랩이 그 자기상관을 흡수한다.

### 2.5 국면(regime)의 정의 — 코드에 고정

감사 §3-3이 "국면 2개 조건이 코드에 없다"고 지적했다. 새 상수 없이 정의한다.

```
regime(d, market) = sign( 벤치마크 120거래일 수익률 at d )     // qa_bench, GL_HORIZ의 120 재사용
'국면 2개를 넘겼다' ⟺ regime=+1 구간과 regime=−1 구간 양쪽에서 각각 사건이 쌓였다
```

## 3. 귀속 — 3층

v5.5의 (A)/(B)/(B\*)/(C) 분류기와 플라시보를 **그대로 재사용한다.** 새로 만들지 않는다.
바뀌는 것은 집계 단위뿐이다: 종목-일 → **진입 사건**.

```
사건 단위 귀속(e) = classifyCause( row_진입일(i), row_청산일(i) )     // 기존 함수
arm별 집계        = {A: n, B: n, B*: n, C: n}  × 결과 사분위 3구간
```

- **(C) 불가피**가 곧 "외부요인" 칸이다. 별도의 전쟁 탐지기를 만들지 않는다.
- (C) 비율 자체는 뜻이 없다. **결과 사분위 세 구간의 차이**만 읽는다(v4.35 무작위 기준선).
- 플라시보(판정 **이전** 같은 길이 창)와의 차이만 해석한다. 이미 v5.5에 구현돼 있다.

## 4. 제안 — 4층. 적용하지 않는다

### 4.1 승급 조건 (감사 §3-6 "상수 변경 최소 조건"을 코드로)

arm X가 arm A를 대체할 **후보**가 되려면 **전부** 충족해야 한다.

```
① 각 군 진입 사건 ≥ 30  ∧  고유 종목 ≥ 15
② 누적 거래일 ≥ GL_MIN_DAYS(250)   — rv별로 센다(감사 §3-3)
③ regime=+1 과 regime=−1 **각각에서** CI90 이 0을 배제하고 **부호가 같다**
④ 주 가설 1개만 사용하고 Holm 보정을 적용한다
⑤ 플라시보 arm D 와의 차이로 판단한다 (A−D vs X−D)
```

### 4.2 충족 시 코드가 하는 일

```
1. 검증 탭 상단에 '변경 후보' 카드를 띄운다. 근거(N·U·CI·국면별 부호)를 전부 펼친다.
2. 그 규칙을 **새 arm으로 자동 추가**하고, 추가 시각을 CONST_LOG 형식으로 기록한다.
   → 그 시점부터 워크포워드 검증이 시작된다.
3. 끝. 상수도, RULE_VER도, 판정 코드도 건드리지 않는다.
```

**왜 이것이 "스스로 발전"의 한계선인가**: 과거 데이터로 규칙을 고르는 것은 그 데이터에
맞추는 것이고(§22-⑤), 자동화해도 성질이 변하지 않는다. 반대로 **후보를 새 arm으로 올려
미래를 더 모으는 것**은 과거를 다시 쓰지 않는다. 시스템은 스스로 가설을 만들고 스스로
검증을 시작하되, 결론은 사람이 `RULE_VER`를 올려서 내린다.

### 4.3 절대 하지 않는 것

- 검증·감사 화면 수치를 보고 임계값 조정 (§22-⑤)
- 승급 조건 자체를 미달 시 완화 — 조건은 `qa_prereg`에 동결되어 있다
- arm을 사후에 추가하고 과거 전체에 소급 — 추가 arm은 추가 시각 이후만 유효
- (C) 불가피를 '참작'으로 바꿔 실패를 상쇄

## 5. 사전등록 — `qa_prereg`

규칙은 `create` 전용이고 `update`·`delete`가 금지돼 있다(firestore.rules:94-98).
앱 부팅 시 문서가 없으면 1회 생성하고, 있으면 **현재 정의의 해시와 대조**해 다르면
검증 탭에 경고를 띄운다(덮어쓰지 못하므로 경고가 유일한 수단이다).

```
qa_prereg/{rv}_shadow_v1 = {
  id:       'v55_shadow_v1',
  at:       <생성 시각>,
  rows:     { arms: […정의…], regime: '…', entry: '…', embargo: '…' },
  outcomes: { primary: 'x60', secondary: 'm60', horizons: [20,60,120] },
  promote:  { minEvents:30, minUniq:15, minDays:250, phases:2, correction:'holm' },
  hash:     <정의 문자열의 해시>
}
```

## 7. 이 명세가 답하지 않는 것 (한계 명시)

- **표본은 늘어나지 않는다.** 가상 체결을 아무리 많이 내도 독립 단위는 등급 진입 사건이고,
  v5.5 발효(2026-09-30) 이후 그 수는 연 수십 건이다. 첫 판독은 **빨라야 2027년 하반기**.
- `price` 기반 경로를 쓰지 않으므로 **장중 변동·최대낙폭은 측정하지 않는다.**
- 거래비용·세금·유동성을 반영하지 않는다. arm 간 **차이**를 보는 도구이지 기대수익
  추정기가 아니다.
- `m{h}`의 모집단은 **사용자의 워치리스트**다. 워치리스트가 편중돼 있으면 중앙값도 편중된다.
  이것은 제거되지 않으며, `mn{h}`와 구성으로만 드러난다.
