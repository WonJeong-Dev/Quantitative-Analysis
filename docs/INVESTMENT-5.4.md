# 5.4 투자판단 개선 및 검증

2026-09-21. 앱 v5.4.0, 규칙 v5.4. 기존 개인·가족 계정의 거래원장을 유지하며 추가한 기능이다. 실계정에 가정을 대신 저장하거나 원격 배포하지 않았다.

## 사용자 기준 반영

- 예상 보유기간: 종목별 1~36개월. 사전 검증은 20/60/120/252/504/756 거래일 중 선택.
- 총자산 초깃값: 원화 40,000,000원. 매수·매도·입출금에 따라 사용자가 현재 금액으로 갱신한다.
- 최소 현금 초깃값: 0원. 현재 현금은 별도 입력이며 추측하지 않는다.
- 종목·업종·공통 테마의 비중 한도와 손실한도: 미정. 미정 상태로 저장할 수 있지만 위험 점검 통과로 취급하지 않는다.
- 기술·성장주와 연계산업: 업종 외에 공통 테마를 직접 지정한다. 예를 들어 반도체·전력·광통신을 모두 ‘AI 설비투자’로 묶으면 같은 집중위험으로 합산한다. 사업분류와 실제 노출은 사용자가 확인해야 한다.

## 1. 점수·용어·미확인 처리

재무 품질은 ROE·영업이익률·부채비율이 모두 확인되어야 계산한다. 하나만 존재할 때 그 항목을 100%로 재정규화하지 않는다. 성장성도 매출 성장과 EPS 성장을 함께 요구한다. 필요한 그룹이 없으면 기존 중립 앵커를 유지하되 결측을 표시하고, 개별 필수 입력 결측도 주식 후보 등급 G11에서 차단한다. 업종에 따라 이 공통 모델 자체가 부적절할 수 있으며, 이 경우 높은 점수를 만들기 위한 임의값 입력 대신 별도 분석이 필요하다.

애널리스트 수가 없으면 목표가를 제외한다. 최근 애널리스트 액션일을 전체 컨센서스 갱신일로 간주하지 않는다. 목표가 기준일 미확인 시 기존 50% 감쇠 정책을 적용한다. 실적 발표일 미확인·지난 날짜는 G9 통과로 간주하지 않고, ETF에는 기업 실적 일정 게이트를 적용하지 않는다.

‘추천’은 ‘후보’, ‘확증’은 서로 연관될 수 있는 충족 조건으로 표시했다. 기존 상승여력 20% 문턱은 유지하되 안전마진이라고 부르지 않는다. 휴리스틱 현재가치와의 괴리는 손실 하한이 아니다. 규칙 v5.4의 기록은 과거 규칙과 분리한다. 로그의 설정 식별값에는 가치지표 가중치를 포함하고 단순 메모는 제외한다.

## 2. 투자정책과 매수 전 점검

상단 **투자정책·검증** 또는 종목 상세의 버튼으로 연다. 로그인 사용자의 모든 원장 계좌를 합산한다. 원장 오류, 가격·환율 미확보/오래됨, 분류 누락은 해당 자산을 0으로 처리하지 않고 점검을 보류한다. 총자산과 원장 평가액+현금이 1원보다 크게 다르면 미대사 금액을 표시하고 보류한다. 현재 약 4천만 원이라는 대략값을 그대로 쓸 경우 이 대사가 맞지 않을 수 있다.

매수예정금액은 원화, 수수료 포함 현금 소요액이다. 매수 후 종목·업종·테마 비중은 같은 총자산을 분모로 계산한다. 편의상 비용 포함 금액 전체를 위험노출로 잡으므로 소액의 보수적 과대평가가 생길 수 있다. 원화 환산 환율은 앱이 확보한 시세를 사용한다.

종목 전액손실 기여도와 공통 테마 동반하락 스트레스를 손실한도와 비교한다. 테마 스트레스는 `매수 후 테마 비중 × 사용자가 입력한 테마 하락률`이며 다른 자산 가격은 그대로 둔 가정이다. 예상손실·최대손실·VaR이 아니다. 한 테마만 직접 지정하므로 다중 사업노출, ETF 내부 중복, 모든 테마의 동시 하락은 자동 모델링하지 않는다.

주식은 보수 시나리오의 현재가치가 현재가보다 높아야 하며, 현재 규칙 후보 조건·실적 일정도 확인한다. 장기 하락추세이면 기존 후보 ‘하’ 표시와 별개로 신규 매수 검토를 보류한다. 실제 주문을 실행하는 기능이 아니다.

## 3. 별도 시나리오 가치평가

정상화 이익 모델 또는 매출→정상화 순이익률 모델을 직접 선택한다. 주당 기초값은 **거래되는 주식/ADR 1주, 시세 통화, 연간 값**이다. 공시 기준일·근거·통화/ADR 조정을 사용자가 입력한다. 기존 자동 주당매출이나 목표가를 검증 없이 새 시나리오의 정답으로 옮기지 않는다.

보수·기준·낙관별로 총이익 또는 매출 성장률, 만기 PER, 요구수익률, 주식수 증가율을 입력한다. 매출 모델은 만기 순이익률도 필요하다. 성장률은 이미 희석이 반영된 EPS 성장률과 구분해야 한다.

```
기간 y = 보유개월 / 12
만기 EPS = 주당 기초값 × ((1+성장률)/(1+주식수 증가율))^y
매출 모델의 만기 EPS에는 만기 순이익률을 추가로 곱함
만기 추정가 = 만기 EPS × 만기 PER
할인 현재가치 = 만기 추정가 / (1+요구수익률)^y
현재가치 대비 할인율 = (현재가치 − 현재가) / 현재가치
```

가정이 빠지면 평가를 보류한다. 보수≤기준≤낙관의 현재가치 순서를 확인한다. 현재가를 잔여 앵커로 섞지 않는다. 배당·재투자 자금·운전자본·부채 만기·유동성·파산확률을 직접 모델링한 DCF는 아니며, 특히 단기 1개월의 설명력은 약하다. 작은 가정 차이로 큰 가치 차이가 생길 수 있으므로 범위를 함께 본다.

기존 휴리스틱 엔진도 PER이 제외되거나 산출 불가능하고 PSR이 업종상 허용되면 사용 가능한 PSR 대안을 확인한다. 대체모델이 더 정확하다고 가정하지는 않는다. ETF에는 이 기업가치 모델을 적용하지 않는다.

## 4. 비용 포함 사전 고정 검증

**현재 조건으로 검증 시작**을 누른 시점의 시장·주식 모집단·규칙·설정·신호·비용·보유기간을 저장한다. ETF는 제외한다. 과거 자료를 보고 선택한 조건을 과거 외표본인 것처럼 소급하지 않는다. 동일 시장의 미완료 검증이 있으면 중복 검증을 생성하지 않는다. UI에서 조건을 덮어쓰는 기능은 없지만, 사용자가 자신의 DB를 직접 수정하는 것을 막는 변조방지 시스템은 아니다.

비교군은 아래 네 가지로 고정하며 개별 종목을 동일가중한다.

- 전체 고정 모집단
- 품질만: Q≥60
- 타이밍만: RSI 하단 (`rsiLo + 0.35×(rsiHi−rsiLo)` 이하), %B≤0.3, 장기 하락추세 아님
- 복합 규칙: 당시 v5.4 후보 등급 존재. 새 수동 시나리오·포트폴리오 매수금액의 성과 검증과는 구분한다.

미국은 S&P 500 가격지수, 한국은 KOSPI 가격지수와 비교한다. 관측 이후 첫 세션 시가 진입, 지정 거래일의 완료된 종가 청산이다. 지수와 종목의 진입·청산 세션이 일치해야 하고, 모집단 전부가 동일 기간이어야 집계한다. 종목이 삭제되거나 상장폐지·거래정지 자료가 없으면 살아남은 종목만 계산하지 않고 미확보로 표시한다.

편도 비용은 매수·매도 양쪽에 적용한다. 주식과 비교지수 가정 비용은 별도 입력이며 0도 직접 입력한다.

`비용 후 수익률 = (1+가격수익률) × (1−편도비용) / (1+편도비용) − 1`

**검증 시세 조회·완료값 보존**은 최대 5년 이력을 별도 조회하며 기존 보드의 2년 계산창을 바꾸지 않는다. 처음 전체 표본이 완성되면 그 수익률·세션·조회시각을 보존하고 다시 덮어쓰지 않는다. 5년을 넘겨 방치해 진입 자료가 사라지거나, 공급자 이력이 불완전하면 미확보다. 보존 전 주가 수정·분할 조정·심볼 재사용 등에 의한 공급자 자료 리비전 위험은 남는다.

**성과는 현지통화 가격수익률이며, 배당·원화 환산·세금이 포함된 총수익률이 아니다.** 지수는 직접 매수 가능한 상품도 아니다. 공통 기간 하나의 종목 수를 독립적인 거래 수로 세어 유의성·Sharpe·승률을 주장하지 않는다. 실제 미래 관측이 필요하며, 현재 높은 예측 정확성을 입증했다는 뜻이 아니다. 최대 10개 검증을 저장하고, JSON으로 가정·결과·한계를 함께 보관할 수 있다.

## 검증 및 배포

- `node scripts/verify.cjs`: 단위·통합·Worker·진단 회귀검사. 이번 변경에 재무 부분결측, 실적일, 모델 선택, 할인율 분모, 비용, 표본 누락, 비중·테마 스트레스 테스트를 추가했다.
- `node tests/investment-browser.cjs`: 로컬 합성 서버를 스스로 시작/종료한다. 1440/768/390/320px에서 정책·시나리오·검증 고정·다운로드 및 최초 결과 보존을 검사한다. Firestore에 직접 중첩 배열을 저장하지 않는지도 검사한다.
- 기존 보드·원장·백업의 브라우저 검사는 별도 수행한다. 운영 Firebase 호출 성공이나 실제 시세 정확성을 합성 검사 결과로 대체하지 않는다.
- `src/investment.js`는 순수 계산, `src/investment-ui.js`는 화면·저장 연결이다. 빌드된 `dist/index.html`에 모두 포함된다.
- 이번 배포는 **dist/index.html 교체**. 기존 favicon.ico·apple-touch-icon.png는 유지. Worker와 Firestore 규칙은 이번 변경에서 바꾸지 않았다.

블랭크파인 관점은 특정 매수 공식을 복제했다는 의미가 아니다. 예측의 한계, 독립적 가치 점검, 집중위험·유동성·스트레스 관리를 참고한 설계다. 검토 근거: [FCIC 증언](https://fraser.stlouisfed.org/archival-collection/financial-crisis-inquiry-commission-4967/testimony-lloyd-c-blankfein-chairman-ceo-goldman-sachs-group-inc-520471/fulltext), [Deflated Sharpe Ratio 연구](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf).

검증 실행 결과: 오프라인 115개 검사 통과. 새 투자화면 1440/768/390/320px 흐름 검사 통과. 기존 보드·원장·가져오기·백업/복구 1440/1024/768/390/320px 검사 통과, 페이지 실행 오류 없음. 실제 운영 Firebase 로그인·저장과 미래 투자성과는 이번 로컬 검사 범위 밖이다.
