# 5.3.0 — 원천 주당매출 정합 수정

## 확인한 증거

2026-09-21 00:59:05 점검 파일에는 77종목, 60개 PSR 상세, 15일치 로그가 있습니다. 조회 실패·가격 이상·데이터 지연 목록은 비어 있습니다. 이 값들은 앱 진단의 결과이며 독립적인 원천 정확성 인증은 아닙니다.

사용자가 제공한 Worker와 Yahoo quoteSummary 원본을 읽기 전용으로 대조했습니다. ASML·TSM의 PSR 원값은 시가총액/재무통화 매출과 일치했습니다. 따라서 그 두 종목의 PSR 환율 나눗셈 자체가 오류라는 주장은 맞지 않습니다. 주당매출 필드의 주당 기준이 총매출·주식수와 맞지 않는 것이 확인되었습니다.

| 종목 | 기존 원천 주당매출 | 재계산 주당매출(USD) | 재계산 PSR |
|---|---:|---:|---:|
| ASML | 1.648044 (EUR 태그) | 105.678984 | 15.896444 |
| TSM | 107.0325 (TWD 태그) | 26.969288 | 16.117224 |
| SPCX | 5.888 (USD) | 1.748171 | 87.354182 |
| QNT | 0.636 (USD) | 0.086469 | 596.511313 |

Yahoo 내부 필드의 일관성을 확인한 값입니다. 기업 공시와 독립 대조한 적정 가치가 아닙니다. 현재 경제적 주식수로 매출을 나누므로 기간평균 희석주식수로 계산된 주당매출과는 차이가 날 수 있습니다.

## 변경

- 총매출 × 환율 ÷ 주식수로 시세통화의 주당매출을 계산합니다. 같은 응답에서 주가 × 주식수와 시가총액의 차이가 1% 이내일 때만 채택합니다. 이 허용치는 동시 응답의 반올림·시점 차이에 대한 검증 기준이며 매수 기준이 아닙니다.
- impliedSharesOutstanding을 먼저 확인하고, 불일치하면 sharesOutstanding을 확인합니다. 둘 다 불일치하거나 필수값이 없으면 자동 주당매출을 사용하지 않습니다. 임의 ADR 배수나 종목별 보정 상수는 없습니다.
- 원천 주당매출은 비교용으로 보존하고, 검증된 재계산값만 적정가 입력으로 전달합니다. 수동 주당매출은 기존대로 우선합니다.
- SPCX와 QNT의 PSR은 기존 상한 80을 넘으므로 자동 주당매출 기반 적정가가 제외됩니다. 상한을 완화하지 않았습니다.
- 수동 PSR(ASML 17.04, QNT 433.76, TSM 16.45)은 표시용으로 보존합니다. 수동 PSR 자체는 적정가 함수의 입력이 아닙니다.
- 산식 입력 기준이 달라져 규칙을 v5.3으로 분리했습니다. 새 로그는 v53_ 날짜 키로 저장하고 v5.2 및 구버전 로그를 삭제하거나 덮어쓰지 않습니다.
- 현재 규칙의 오늘 로그를 읽은 경우 이를 저장 완료로 인식합니다. 구버전 로그는 새 규칙의 저장을 막지 않습니다.

## 배포 순서

1. Cloudflare의 기존 Worker를 backend/cloudflare_worker.js 전체 내용으로 갱신합니다. 기존 Secret과 설정은 유지합니다.
2. /summary?sym=ASML 응답에서 workerBuild=5.3.0, revenueBasis.status=reconciled를 확인합니다.
3. GitHub Pages 배포 위치에 dist/index.html과 두 아이콘을 올립니다.
4. 앱에서 `⟳ 전체 갱신`을 누릅니다. 이 버튼은 이제 재무 캐시도 갱신합니다. 구버전 캐시에 재계산 근거가 없으면 자동 주당매출을 사용하지 않고 worker-update-required로 표시합니다.

현재 운영 Worker 응답에는 deRatio가 없었습니다. 프런트엔드는 기존 de 퍼센트값을 변환하는 호환 처리가 있어 부채비율 전체가 잘못됐다는 의미는 아닙니다. 새 Worker를 함께 배포해야 신·구 버전 혼용이 해소됩니다.

PBR의 원천 주당순자산 기준은 이번에 검증하지 않았으며, 총매출 검증이 PBR의 정확성까지 보장하지 않습니다. 원격 배포·실계정 쓰기는 수행하지 않았습니다.
