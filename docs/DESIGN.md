# QA Stock Board — 현재 설계 (5.5)

> 5.5 변경은 [CHANGES-5.5.md](CHANGES-5.5.md). 아래 불변조건에 5.5에서 세 가지를 더했다:
> ① 신뢰 가중(tw)과 '다른 값의 크기를 재는 자'로서의 원시 입력을 구분한다(이상치 배제·가중 분기는 원시 목표가 기준).
> ② 판정 불가는 통과가 아니다 — 근거가 목표가뿐인 현재가치로 G4·C1을 판정하지 않는다.
> ③ 판정 로그·사전 고정 검증 보관본은 규칙 차원에서 불변이다(생성 시각은 서버 시각).

현재 목적은 본인·가족의 판단 근거 확인과 원장 정확성입니다. 외부 투자자의 공인된 공식이라고 표방하지 않습니다. ‘블랭크파인 관점’은 기존 프로젝트가 정의한 안전마진·품질·하락추세 방어의 설계 취지로 보존했습니다.

## 변경할 때 유지할 불변조건

- 단위·통화·주당/총액·관측시각·기준기간을 서로 섞지 않습니다.
- 모르는 값은 null 또는 미확정 상태로 두며 0이나 가정한 성장률로 둔갑시키지 않습니다.
- 거래 원본은 계산 결과와 분리합니다. 분할은 수량·단가를 역비례 환산하여 거래금액을 보존합니다.
- 실제 계좌는 분리하고, 종목명은 식별자가 아닌 표시 속성입니다.
- 과거에 관측하지 않은 판단을 과거 거래의 판단으로 기록하지 않습니다.
- 모델 입력·설정과 결과를 함께 추적합니다. 서로 다른 규칙·설정·불명확한 과거 스냅샷을 검증 표본으로 섞지 않습니다.
- 매수 등급의 숫자 임계값 변경에는 사전 가설과 별도 기간 검증이 필요합니다.

## 데이터 구조

기존 사용자 UID 아래 10개 컬렉션을 유지합니다. 경로는 C/D 함수만 조립하며, 현재 로그인 UID와 세션 UID가 다른 경우 접근을 중단합니다.

추가 필드는 거래의 `sequence`, `sourceId`, `snapshotStatus`, `snap.observedAt`, `snap.instrument`, 재무의 `deRatio`, 수동값의 `deUnit`, 판정 로그의 `schema`, `policy`, `inputs`, `settings`입니다. 기존 문서를 일괄 덮어쓰는 마이그레이션은 없습니다.

판정 로그 스키마 2는 최초 일별 관측을 트랜잭션으로 저장하고 같은 날 다시 덮어쓰지 않습니다. 수익률은 다음 세션 시가 진입으로 명시하며, 종목/지수 수익률의 완료 상태를 각각 복구합니다. 과거 스키마는 보존하되 새 검증 집계에서는 제외합니다.

## 개발 과정

현재 코드 구조와 실행 방법은 [README](../README.md)를 참고하세요. 코드를 수정하면 순수 함수→앱 통합→Worker→브라우저 순으로 확인하고 배포물을 다시 생성합니다. 과거 사건의 서술을 현재 동작 명세나 실행 지시와 혼동하지 않습니다.

수수료·배당·환전 출금까지 포괄하는 세후 총수익률, 브라우저 미실행일의 서버 수집, 거래소별 과거 데이터의 전면 백테스트는 구현 범위 밖입니다. 현재 UI는 해당 값들을 보장된 손실 한도나 검증된 초과수익으로 표현하지 않습니다.
