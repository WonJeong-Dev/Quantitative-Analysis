# QA Stock Board 5.5.0 — 감사 결과와 변경 기록 (2026-09-30)

- 대상: 5.4.0 전체(`src/`, `backend/`, `tests/`, `scripts/`)
- 구성 요소 버전: 판정 규칙 **v5.5**(`RULE_VER`), 워커 **v7.0**, 보안 규칙 **v5.5**
- 판정이 바뀌는 변경과 바뀌지 않는 변경을 나눠 적었습니다. 판정이 바뀌는 것은 ★로 표시했습니다.

## 4. 보안·배포

- **워커 v7.0**
  - 모든 요청에 Firebase ID 토큰(RS256)을 요구합니다. `ALLOWED_EMAILS`가 없으면 503(fail-closed)입니다.
  - Origin은 반사 방식입니다. 인증을 통과한 뒤에 캐시를 조회합니다.
  - 캐시 키는 정규화하고, 부분 성공은 캐시하지 않습니다.
  - KRX를 https로 호출합니다. `KRX_SCHEME=http`로 되돌릴 수 있습니다(지원 여부는 미실측).
  - raw/diag는 인증 필수입니다.
  - 크럼은 상태와 형식을 검사합니다. 야후 429는 냉각합니다.
  - 상류 본문은 8MB로 제한합니다. 500 응답에 오류 원문을 싣지 않습니다.
  - GET만 받고, URL은 4096자로 제한합니다. 선택 레이트리밋은 인증 뒤 사용자 단위로 겁니다.
- **앱**: 설정된 워커 origin으로 가는 요청에만 Bearer 토큰을 붙이고, 401이면 토큰을 갱신해 1회 재시도합니다.
- **규칙 v5.5**
  - `qa_gradelog`
    - 생성: 문서 id `v55_YYYY-MM-DD`, `sat == 서버 시각`, 그 날짜의 KST 하루(+1시간) 안에서만 가능합니다.
    - 수정: `fwd`만 가능합니다.
    - 삭제: 불가합니다.
  - `qa_prereg`: 생성만 가능합니다.
  - ★ 에뮬레이터 실행 검증은 하지 못했습니다(작업 환경에서 에뮬레이터 jar 다운로드가 차단됨). `tests/firestore-emulator.cjs`에 단정 19개를 넣어 두었습니다.
- **CSP·SRI**
  - Firebase compat 10.14.1을 `vendor/`에서 자체 호스팅합니다. 파일은 npm `firebase@10.14.1`과 바이트 단위로 같습니다.
  - 빌드가 SRI sha384와 인라인 스크립트 sha256을 계산해 `<head>`에 CSP로 넣습니다. 줄바꿈은 LF로 정규화합니다.
  - `connect-src`는 제한하지 않습니다. 워커 주소가 사용자 설정값이기 때문입니다.
