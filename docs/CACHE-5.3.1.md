# 5.3.1 — 재무 캐시 스키마 갱신

2026-09-21 01:16:20 점검 파일에서 60개 주식 전부의 revenueBasis가 없었습니다. 재무 수집시각은 00:49:31~00:50:34로, 이전 파일과 같습니다. 현재 운영 Worker의 일반/진단 응답은 5.3.0과 reconciled 근거를 정상 반환했습니다.

원인: 앱이 3일 이내 캐시를 재사용하면서 새 revenueBasis 스키마 유무를 검사하지 않았습니다. 원천에 자료가 없다는 결론이 아닙니다.

수정: 새 스키마가 없는 주식 캐시를 자동 재조회합니다. 실패나 구버전 응답에는 5분 재시도 간격을 두며 전체 갱신은 즉시 재시도합니다. ETF는 이 재조회에서 제외합니다. 스키마가 존재하지만 원천 자료가 부족한 상태는 계속 재요청하지 않습니다. 이관 요청은 schema=1 쿼리로 구버전 URL 캐시와 구분합니다.

표시: worker-update-required를 revenue-basis-missing로 바꾸었습니다. 구버전 캐시만으로 Worker 미배포를 단정하지 않습니다.

판단 규칙은 v5.3 그대로입니다. 현재규칙 로그 1건과 이전규칙 로그 15건을 삭제·덮어쓰기 하지 않습니다. 첨부 시점의 등급과 오늘 최초 로그는 자동 주당매출이 없는 상태의 관측일 수 있으므로 갱신 후 완전한 입력으로 산출한 값과 구분해야 합니다.

이번에는 dist/index.html만 갱신하면 됩니다. 운영 Worker는 5.3.0 그대로 사용합니다. 배포 뒤 전체 갱신으로 즉시 재조회할 수 있습니다.
